# Immutable multilingual scanner

Language selection uses file extensions, never benchmark names, labels or inferred vulnerabilities. Supported labels are Java, Python, Go, JavaScript, TypeScript, PHP, Rust and Ruby. Every region receives every check in its fixed language profile, plus `context_missing`; there is no probabilistic routing.

| Profile | Security checks |
| --- | ---: |
| Java, Python, Go, PHP, Ruby | 14 |
| JavaScript, TypeScript | 15 |
| Rust | 15 |

All profiles retain the eleven historical category IDs/metadata and add `ssrf`, `codei`, `deserialization`. JS/TS alone add `prototype_pollution`; Rust alone adds `unsafe_memory`. Portable category criteria are paired with native APIs and safe-use contrasts in `profiles.rs`. Presence of an API, parser, unsafe block or untrusted session value does not alone establish a weakness. Low-level memory judgments require a concrete violated invariant. These are bounded-source AI checks, not parsers or whole-program analyses.

Extensions: `.java`; `.py/.pyw/.pyi`; `.go`; `.js/.jsx/.mjs/.cjs`; `.ts/.tsx/.mts/.cts`; `.php/.phtml/.php5/.php7/.php8`; `.rs`; `.rb/.rake/.gemspec`, plus exact Ruby filenames `Gemfile`, `Rakefile`, `config.ru`. Extensions are case-insensitive. Extensionless shebang scripts are unsupported (no shebang inference). Python stubs are eligible, but may provide little executable context. TypeScript declaration-only `.d.ts/.d.mts/.d.cts`, minified JS/CSS and source maps are explicitly excluded, not reviewed. Existing hidden/generated/dependency paths remain excluded; Python `venv`, `env`, `__pycache__`, `site-packages` are also excluded. Ignore rules, custom globs and symlink restrictions apply to context collection exactly as to scanned files; the sensitive-source exclusion runs before a file can enter the helper index, so an excluded file can never leak into a request through a helper reference.

Source remains plain readable text, never base64. Files up to 24 KiB are sent whole, with no 200-line cap. Larger files use exact, line-aligned regions up to 24 KiB, normally overlapping 30 lines; overlap is reduced for short byte-bounded regions or when necessary to include new lines. Unicode, CRLF and final unterminated lines are preserved. The 1 MiB file, 8 KiB line and 24 KiB chunk bounds remain; there is no cap on total files, regions or snapshot bytes — the preview manifest and user authorization bound the upload. No AST or call-graph resolution is performed; cross-file context is limited to the deterministic name-reference helpers described below.

`Chunk` persistence is unchanged. Region and preview metadata report language and actual profile counts. Preview checks are the deterministic metadata-order union of checks requested for included languages only. `state.language` and `state.check_pack_version` (`contextual-v5`) are part of the serialized request hash, alongside all question text; changing any invalidates cached requests naturally. `state.file_complete` and `state.context_policy` distinguish whole-file from partial context. Multi-region files add `state.file_outline`: up to 48 lexical signature lines (2 KiB cap) for the surrounding file, honestly labelled as signatures, not implementations. `state.helpers` embeds bounded same-repository context: inventory is two-pass, so after the walk every included source file is indexed by its file-name stem and every eligible context file (`is_context_file`: `.properties`, `.xml`, `.yaml/.yml`, `.toml`, `.ini`, `.cfg`, `.conf`, `.json`; never lockfiles or `.env`) by full file name. For each region, identifier tokens (including dotted segments) that match another file's stem, or string text containing a context file's name, attach that file's full source to `state.helpers` — at most 4 helpers, 16 KiB each, 48 KiB total, keyed by repository-relative path. Selection is deterministic (token order, no randomness) so request hashes stay reproducible; helper content is hashed into the request and counted in `preview.estimated_tokens`. `preview.context_files` reports the eligible context-source count. Helpers are full file text honestly labelled as referenced context; they are not a resolved call graph, and an unreferenced or oversized file is simply absent. Cross-file taint tracking is not supported yet: a request can show the referenced file's text, but nothing traces whether a specific value flows from one file into a sink in another, and `context_policy` says so in every request. Native guidance and common review policy occur once in `state.native_guidance` and `state.review_policy`; category questions reference them with backticked `state.*` paths. Source/comments remain untrusted evidence, never instructions. Describing or detecting a vulnerability is not performing it: command detectors, non-sensitive locale cookies, ID tracking, and CSS assigned to a style element are not sufficient evidence of command execution, credential-cookie risk, authorization failure, or JavaScript execution respectively. This does not declare all `textContent` assignments safe, especially for script elements. `context_missing` requires an actual plausible security-relevant operation whose assessment depends on missing information, not merely unrelated omitted functions or irrelevant categories.

Beyond category Nouls, each request asks typed questions the model answers against the same state: `sink_pointer` and `source_pointer` Choices over up to 12 code-extracted call identifiers plus `none_visible` (omitted entirely when no call pattern exists), and an `impact` Score on a fixed 0-3 scale. These are candidate evidence pointers and a routing weight, never proven sinks, sources or impact.

Preview `limit_reached` and sorted `limit_reasons` record actual bound-triggered exclusions (oversized files, over-long lines), not merely reaching a count exactly. `exclusion_reasons` counts observed skipped entries and sums to `excluded_count`; unsupported extensions remain separately counted in `unsupported_count`. Exclusion examples are capped at 100, not the totals. Pruned directories count as observed entries, not all descendants. The 100,000-entry enumeration guard still fails inventory rather than returning a misleading partial snapshot.

`parse_response(value, request)` requires exact answer keys from the saved request, known question IDs, `context_missing`, answer types matching each requested type, noul probabilities in [0,1], Choice answers whose declared option is a criteria key (the distribution is validated but need not favor the declared option — `choice` is the answer per the API contract), Score answers with a legend equal to the requested levels, in-range score, and valid distributions/confidence, pinned request/response model, and nonnegative integer token usage. It deliberately does not compare saved questions against today's profiles, so legacy eleven-check Java history (Noul-only, no pointer or impact questions) remains valid. Extra or missing answers are rejected.
